## The core loop

1. **`CreateDD`** — render workspace objects into `<FDD>_<ShortName>_DataDict.m`. Details: [Create & verify DD](create-verify-dd/).
2. **`VerifyDD`** — check the dictionary and its agreement with the model. Same page.
3. **`STool`** — orchestrate the full design package. Details: [STool hub](stool/).
4. **Reports & keywords** — requirements, Model Advisor, DD reports and naming compliance. Details: [Reports & keywords](reports-keywords/).

Supporting tools handle discovery (`NxtrFindFDDMdl`, `NxtrChkFDDData`, `NxtrElecArchTypFindr`, `NxtrFDDNoNmeGenr`), file hygiene (`NxtrFileMgr`), packaging (`NxtrPckGen`), datatypes (`NxtrDTMgr`, `NxtrDTTbl`), cross-program checks (`NxtrWrgUsgChk`), environment (`NxtrToolsPahFindr`, `NxtrToolsVersFindr`, `NxtrLicChkOut`) and traceability hooks (`NxtrLnchDoors`, `NxtrDDGenr`, `NxtrUpdRpt`, `NxtrWebViewGenr`, `NxtrCosmeticUpdr`, `NxtrXlsRead`).

:::caution[Generated files are outputs]
Every `.p` file ships next to its `.m` source, and every generated report/dictionary is rebuilt by the tools. Fix the inputs (objects, models, helpers) — never the outputs.
:::
